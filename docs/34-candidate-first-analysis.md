# 34 · 候选优先分析与成本止血

设计日期：2026-11-05。先修正自动准入和积压处理，再建设热点发现；本节不代表已接入 X 或已更新生产。

后续通知策略由 [38 机会通知降噪](38-opportunity-notifications.md) 收紧：原始链上发现不能再通过 `includeRoutineEvents` 放行，其他链上机会须满足核验与参与条件，发送前复查旧积压。下列显式选择链上观察的条款记录本节初版行为，以38节最终契约为准。

## 根因与产品路径

普通新池、部署、mint 和状态快照是观察事实，不自动构成研究机会。旧实现只检查 AI 配置，导致每个新事件均付费分析；旧示例通知规则又把这些事件全部纳入。两者独立：确定性通知原本已不等待 AI，但 outbox 按时间混排会被分析积压挤占。

目标路径是：授权资讯/社交采集 → 实体与主题聚合 → 免费的确定性筛选 → 有限候选 → AI 研究 → 符合通知条件的研究提醒。严重风险保留独立确定性通道，不等待 AI，也不能被机会分抵消。BRC20 是否仍有热度不能由系统臆断；普通 mint 不自动付费，与特定板块的市场判断无关。

## 本轮实现契约

- live 自动分析只允许新鲜、置信度至少 0.8、已验证的 `OFFICIAL_ANNOUNCEMENT` / `PROTOCOL_RELEASE` / `EXCHANGE_LISTING`，以及带已确认严重风险标志的事件。新闻列表不是已识别的热点，不自动调用 AI。Fixture 仍只走明确标注的合成 Provider。
- 来源发布时间已知时和首次发现时间均须在最近一小时内，拒绝未来或无有效发现时间的事件；未知发布时间保持未知。事件保存前和实际调用前共用准入策略。低价值/过期/超额任务记录 `SKIPPED` 与原因，保留事实与已完成分析，旧 Redis 任务消费时同样检查，不继续付费。
- 每日真实调用默认上限 20 次，和现有金额预算同时约束；重试也计次。预算耗尽候选终止为跳过，不日复一日积压。服务器环境 `AI_MAX_DAILY_CALLS` 可设为 0 暂停新调用。
- live 待分析 outbox 默认最多 20 条，同资产六小时内只接纳一次候选；事务锁保护多副本。准入饱和时显式跳过，不把丢弃的候选显示为已分析。此冷却不是热点聚类。
- outbox 通知优先且独立取数；live 分析同时最多派发两个，避免 Redis 等待时间超过租约后重复补投。恢复时分批结束不合格历史任务；实际执行前仍复查策略与每日额度。
- 模型输入限制为最多 5 条证据、每条 2400 字符、正文总计 8000 字符；不发送整段大批量链上原始响应。
- 通知规则增加 `includeRoutineEvents` 显式选择，默认 false；普通 `PAIR_CREATED` / `NEW_TOKEN_DEPLOYED` / `MINT_CREATED` / `MINT_STARTED` / `TOKEN_STATE_SNAPSHOT` / `MARKET_SNAPSHOT` 不命中通用规则，确定性严重风险不受此默认过滤影响。规则测试和实际通知使用同一判定。旧规则未提供该字段时采用安全默认；界面允许有明确需求的用户选择。
- 无数据库结构迁移，不删除事件、分析账目或通知记录，不运行 Redis 清库。生产在途请求不能撤销已经发生的供应商费用。

## 后续热点发现边界

该设计初版时尚无 X/KOL connector。后续本地实现见 [36 免费X采集](36-free-x-collection.md)：自建授权登录态采集、账号范围与原创主题聚合，仍须部署采集器并配置真实会话后验证。不可把 RSS 或通用 `SOCIAL_MOMENTUM` 算法显示成已监控 X。

后续候选按可靠项目/合约实体、主题与窗口聚合，保存原帖 ID、作者、原创/转发关系和公开时间；去掉重复、转发与广告，再比较独立原创作者数、相对历史基线增长、新颖性、官方佐证和参与路径。作者提及数与独立组织证实分开；同名 ticker 不自动合并。阈值需要真实采样评估，不编造历史命中率。

AI 每主题只分析一次，只有新增重大证据或冷却到期且仍有热度才重分析。研究结论必须区分事实/推断/证据不足、可参与阶段和独立风险；没有可信参与路径的讨论进入观察摘要。当前 AI 仅补充事件摘要，尚无 AI 研究结论驱动的热点外发工作流，本轮不伪称已经完成。
