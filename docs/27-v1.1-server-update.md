# v1.1.0 已部署服务器更新步骤

适用于已经在 `/opt/financial-radar` 运行的 Linux amd64 部署。服务器仅更新 API/Worker 镜像；当前前端托管迁移目标为 Vercel，项目/Secrets、实际发布与用户最后执行的域名映射见 [发布说明](23-release-and-update.md)。目标版本 `v1.1.0` 的实际发布结果以 [Release](https://github.com/AmazingZ-sys/financial-radar/releases/tag/v1.1.0) 和对应 Actions 为准，必须等待 API/Worker 镜像、image-manifest 和对应前端部署完成后执行。历史 tag 使用当时的发布配置，不能以重试迁移前的 tag 声称 Vercel 迁移成功。

本轮新增 AI 中转配置、通知渠道配置和多领域 RSS/Atom 新闻；没有新增数据库结构迁移。部署脚本仍会校验并执行已有的幂等迁移。无需在服务器安装 Node/pnpm，也不需要手工构建镜像。

## 1. 保留配置，备份旧版本

在 SSH 终端执行：

```bash
cd /opt/financial-radar
sudo git status --short
sudo bash infra/scripts/backup.sh
```

如果 Git 显示受版本控制文件被修改，先检查并保留这些修改，再继续；不要使用 `reset --hard`。生产 `.env`、`deploy.env`、`.deploy` 和 Docker 数据卷必须保留。已有数据库/Redis密码、管理员密码和 SESSION_SECRET 继续使用原值，不重新执行首装生成脚本。

## 2. 获取同一版本的部署文件

```bash
cd /opt/financial-radar
sudo git fetch --tags origin
sudo git switch --detach v1.1.0
```

这一步仅切换 Git 管理的文件，忽略的服务器配置和 Docker 数据卷保留。运行中的容器在部署命令执行前继续使用原镜像。

## 3. 确认运行模式和加密根密钥

```bash
sudoedit /opt/financial-radar/.env
```

确认 `DATA_MODE=live`；`WEB_ORIGIN=https://radar.amazingzsys.site`、`SECURE_COOKIE=true`、`COOKIE_SAME_SITE=Lax` 保留原正确配置。

首次使用页面保存 AI/通知凭据前，建议设置 `INTEGRATION_ENCRYPTION_KEY`，至少32字符。可在服务器终端运行 `openssl rand -hex 32` 生成一次，填入 `.env`，并将该值与数据库备份分别安全保存。API 与 Worker 读取同一 `.env`，必须使用同一密钥。不要把值粘贴到聊天、Git或前端环境变量。

为空时兼容使用原 SESSION_SECRET 加密，因此新增变量不是启动必需条件。如果已经通过新版本保存过凭据，保持原有效根密钥；不能随意更换。此前使用 SESSION_SECRET 回退时，可将其完全相同的值作为独立根密钥，或更换后重新填写全部集成凭据。

本轮不要求先在环境变量填写 AI/通知凭据：启动后在页面配置即可。旧环境变量仍作为首次保存前的默认配置。BLS/EIA等未实现的适配器及授权实时股票/黄金/原油行情不会因更新自动出现。

当前宿主端口为 `127.0.0.1:13000`。已使用该端口时无需修改 Nginx；若仍使用旧宿主3000，先按 [已有部署迁移到13000](24-server-api-radar-amazingzsys-site.md#9-已有部署从宿主-3000-迁移到-13000) 同步该项目的 Nginx upstream 和 `deploy.env` 的 HEALTH_URL，再继续。

## 4. 更新 API 与 Worker

```bash
sudo bash /opt/financial-radar/infra/scripts/deploy.sh --version v1.1.0
```

脚本校验 Release 清单和镜像 revision，按不可变 digest 拉取两个镜像，备份数据库，执行迁移，更新 API/Worker，再检查两者健康及 Nginx。运行期间 API 可能短暂不可用。数据库与 Redis 卷保留；不使用普通 `docker compose up` 代替脚本，因为普通命令不会自动加载 `.deploy` 保存的镜像摘要。

## 5. 验证版本与新入口

```bash
sudo cat /opt/financial-radar/.deploy/current
sudo bash /opt/financial-radar/infra/scripts/check-health.sh
curl --fail --silent --show-error https://api.radar.amazingzsys.site/health | jq
curl --fail --silent --show-error https://api.radar.amazingzsys.site/ready | jq
cd /opt/financial-radar
sudo docker compose --env-file .env logs --tail 100 api worker
```

`.deploy/current` 和 `/health` 的版本应为 `v1.1.0`，`/ready` 返回成功。打开 [前端](https://radar.amazingzsys.site)，刷新后登录：

- 系统管理 → AI Provider 配置：填写中转服务的 HTTPS API 根地址（通常以 `/v1` 结尾）、模型、Key，保存后测试；中转不支持 JSON 模式时关闭该开关。
- 通知中心 → 配置渠道：填写 Telegram / 飞书 / Bark，保存后发送测试。平台接受不代表用户已读。
- 数据源 → 查看宏观、财经、科技、全球热点，或新增公开 RSS/Atom。内置来源在 Worker 启动后注册，自定义订阅约15秒内同步；实际采集失败以健康状态为准。BBC 在本地直连有网络限制，服务器需实际核验；配置成功不保证所有源网络可达。

## 6. 更新失败时

部署脚本在应用健康或 Nginx 校验失败时会尝试恢复上一已验证应用。需要手动应用回滚时：

```bash
sudo bash /opt/financial-radar/infra/scripts/rollback.sh
sudo bash /opt/financial-radar/infra/scripts/check-health.sh
```

回滚不逆转数据库，也不更换加密根密钥。本轮没有结构迁移；保留新版本配置以便重新升级。不要删除目录、重新生成数据库密码或执行 `docker compose down --volumes`。
