# 产品需求与验收契约

## 目标用户与价值

管理员希望在新闻扩散前发现新协议/资产；研究者需要知道何时可发现、证据是什么、当前是否可参与、有哪些未知风险。系统展示信息辅助研究，不给出收益保证。

## 功能验收

| 功能     | 验收行为                                          | 数据诚实要求                           |
| -------- | ------------------------------------------------- | -------------------------------------- |
| 认证     | 登录、退出、会话过期、写请求 CSRF、管理员权限     | 密码哈希，响应不返回密钥               |
| 仪表盘   | 从 API 读取采集/事件/机会/通知/Worker 状态        | 指明统计窗口、来源和模式               |
| 热点事件 | 分页、关键词/资产/分类/优先级筛选、详情和证据     | 发布时间/发生时间/发现时间分离         |
| 早期机会 | 独立评分、项目详情/阶段/信号/时间线               | 未验证项目不得声称安全或官方确认       |
| 行情     | BTC/ETH 与宏观扩展位、历史图表                    | 没有数据时为空；来源、时间、延迟明确   |
| 规则     | CRUD、启停、结构校验、测试、触发记录              | 不执行表达式代码，记录版本和触发原因   |
| 通知     | 渠道启停、测试、历史/重试/偏好                    | SENT 只表示平台接受；Fixture 不外发    |
| 来源     | 健康、成功/失败、新鲜度、轮询配置                 | 不把最近一次成功等同于持续健康         |
| 系统     | 服务/版本/队列/AI 预算与失败、日志、设置/观察列表 | 缺失信息显示未知                       |
| 回放     | asOf 截止过滤、信号/分数/通知解释                 | 不用未来数据，不伪造 ORDI 收益或时间线 |

## 非功能验收

- 前后端 TypeScript strict；共享 Zod；OpenAPI 可生成前端类型。
- PostgreSQL 是事实来源；Redis 仅队列/缓存/锁/限流；失败可重放，不丢原始信息。
- 外部请求超时、退避、限流、熔断；日志请求 ID；安全关闭；通知幂等。
- UI 默认中文，深浅主题，移动布局，加载/空/错/重试，键盘可用与表单标签。
- 生产 PG/Redis 端口不暴露，镜像不以 latest 为唯一依据，迁移向前兼容，失败恢复保留数据卷。

## 覆盖层级

第一轮提供所有主要业务域的可运行基础及扩展契约。全量 Bitcoin/EVM/Solana 实时索引、付费黄金/原油行情、商业新闻再分发、真实 ORDI 历史重建、生产云发布需要外部权限或授权。必须逐项记录实现、Fixture、未接入或待验证，禁止合并为“已完整覆盖”。

## 时效目标

官方 RSS 依轮询周期，链上索引依上游延迟，日度国债/FRED 不称为实时报价。采集、标准化、检测、排队、渠道接受均留 UTC 时间；P50/P95 来自实际记录，样本不足显示无数据。高优先级规则不等待 AI。
