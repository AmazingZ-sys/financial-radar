# 12 · Web 控制台设计

设计日期：2026-11-02。本文为业务实现前的设计基线；验收结果另见实施记录。

## 1. 产品与视觉方向

Financial Radar 是面向研究者的金融发现终端。默认首页同时回答：系统是否正常采集、刚刚发生什么、哪些早期项目值得核验、风险在哪里。视觉采用精密仪器式金融终端：深海蓝背景、浅灰高对比文本、薄分隔线、青绿色状态、酸橙色机会强调、琥珀风险色。P0 为红色，颜色之外始终显示文字与图标。

主界面使用固定侧栏、顶部状态带和可滚动工作区。桌面侧栏约 224px，内容最大宽度约 1600px；1440px 下双列主体为 2:1。移动端侧栏改为抽屉，表格横向滚动或转为卡片，筛选面板折叠。数据密度通过 4/8px 间距网格控制，正文不低于 13px，关键数值采用等宽字体。

字体优先使用本机可用的中文苹方/思源黑体，英文标题 Georgia 风格衬线或本机替代，数字使用 SFMono/Consolas；不依赖外部字体请求。圆角控制在 6–12px。背景允许极弱的雷达网格，不使用影响数值可读性的动效。进入动画仅用于初始加载，尊重 prefers-reduced-motion。

主题通过 CSS 变量实现，默认深色，浅色使用暖白底与深蓝正文。主题偏好可本地保存；第三方凭据、会话令牌绝不进入 localStorage。语言默认为 zh-CN，文案集中为语言字典，时间与数字经过统一格式器，后续可替换 i18n 实现。

## 2. 技术与组件边界

- Vue 3 Composition API 与 `<script setup lang="ts">`；TypeScript strict。
- Vite 构建、Vue Router 管理路由、Pinia 保存用户/主题/导航偏好。
- TanStack Vue Query 保存服务器状态；列表 15–30 秒轮询且页面不可见时暂停。写操作成功后精准失效相关 Query。
- 唯一 API Client 管理 credentials、请求 ID、CSRF、超时、错误解码与 Zod 响应校验。浏览器不能直接访问金融或 AI 私密 API。
- Element Plus 提供表单、对话框、日期筛选与通知；Tailwind 提供布局工具；全局设计变量覆盖默认组件色彩。
- ECharts 提供行情与发现趋势图；组件必须处理 resize、主题切换及卸载 dispose。
- OpenAPI 是接口事实来源，生成类型保存在可再生文件内；运行时仍由 Zod 验证关键响应。

公共组件包括 AppShell、PageHeader、DataState、SourceBadge、PriorityBadge、ScoreBar、MetricCard、EvidenceList、Timeline、Timestamp、FilterBar、Pagination、ConfirmDialog。项目机会与风险显示为两条独立评分，未知评分为“尚未评估”，不能用 0 替代。

## 3. 路由和交互

| 路由             | 内容                                                                 | 必要交互                                           |
| ---------------- | -------------------------------------------------------------------- | -------------------------------------------------- |
| `/login`         | 单管理员登录                                                         | 密码隐藏、提交中禁用、错误提示、无明文凭据缓存     |
| `/`              | 今日采集/事件/新项目/通知指标，早期机会、事件流、源健康、Worker 状态 | 点击卡片进入对应列表，刷新和时间范围               |
| `/events`        | 分页事件流                                                           | 分类/资产/优先级/关键词/时间过滤，URL 保存查询条件 |
| `/events/:id`    | 事实、时间、来源、证据、AI 结论                                      | 原始来源链接、模型与提示版本、未验证标记           |
| `/projects`      | 早期机会中心                                                         | 链/阶段/风险过滤，评分排序、监控/取消监控          |
| `/projects/:id`  | 项目概要、评分解释、指标与生命周期时间线                             | 原始来源、证据、独立信号、风险与参与条件           |
| `/markets`       | BTC/ETH 及可用宏观行情                                               | 资产选择、时间范围、来源/采样时间/延迟标识         |
| `/rules`         | 规则管理                                                             | 创建、编辑、启停、删除确认、安全规则测试、触发记录 |
| `/notifications` | 渠道状态、发送记录、失败原因                                         | Telegram/SMTP 邮箱测试、启停渠道、偏好与冷却设置   |
| `/sources`       | Connector 与健康记录                                                 | 启停、轮询周期、最后成功/错误/下次计划             |
| `/system`        | 服务版本、队列、AI 用量、账户、观察列表、设置                        | 修改设置、退出登录、只显示密钥配置状态             |

规则编辑器只支持预定义字段与比较运算符，无脚本输入。保存前展示参数摘要。风险过滤与最低机会评分分别设置。系统页配置 AI 中转地址/模型/预算，通知中心配置渠道，数据源页提供分类目录与 RSS/Atom 新增。凭据输入不持久保存在浏览器，不回显服务器旧密钥；显示环境默认/控制台覆盖、空白保留和明确清除状态。详细交互契约见 [25 可配置集成](25-configurable-integrations.md)。

## 4. 数据真实性和状态

所有页面读取 API。Fixture 模式在全局顶栏永久显示“演示数据 · Fixture”，每条相关证据带 fixture 标签；关闭 Fixture 后清空不存在的行情，不用静态默认值补位。后端不可用时展示错误和重试，不回落为假在线。

图表必须显示资产、单位、数据来源、最近数据时间、粒度和延迟类别。宏观日度数据标“日度数据”；缺少授权的黄金/原油数据标“未配置数据源”。未知的预期值、参与地址、费用、项目团队身份都显示“未知/待核验”。

每个查询有 loading、empty、error、retry 四种状态。后台刷新时保留已有数据显示更新时间，初次加载使用骨架屏。错误正文供用户理解，详细 requestId 可复制。无数据不代表服务异常；API 故障不显示零值统计。失败写操作保留表单内容。

时间存储与 API 传输为 UTC ISO 8601，界面以用户时区显示并提供完整时间提示。事件发生、来源发布、首次发现不能混用。

## 5. 可访问性与验收

按钮有可见标签或 aria-label；对话框可用 Esc 关闭并恢复焦点；表单 label 关联输入；键盘可到达导航、筛选、详情和操作；风险不只用颜色区分。焦点边框始终可见，深浅模式保持正文对比度。

验收覆盖 1440×900、1024×768、390×844：无页面级横向溢出，导航可用；登录/退出、规则 CRUD、筛选/详情、来源切换、通知测试、主题切换可操作；API 故障可恢复；浏览器构建产物无私密配置；控制台无未处理异常。Playwright 使用 API 测试环境，禁止把请求拦截后的 Fixture 当作真实生产联通证据。
