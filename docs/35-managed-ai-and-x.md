# 35 · 管理页调用额度与 X 官方接入

> 本文为被替代的官方API设计记录。用户后续明确采集预算为0并接受自建授权登录态，当前实现以 [36 免费X采集](36-free-x-collection.md) 为准；不购买或自动回退任何付费数据接口。AI管理部分仍适用。

设计日期：2026-11-05。用户选择 X 官方 API；本轮不使用第三方转发接口、不索取聊天中的密钥，不把本地实现视为生产接通。

## AI 次数管理

`AIConfig.maxDailyCalls` 为整数0..500，默认20；数据库旧记录缺少字段时回退服务器 `AI_MAX_DAILY_CALLS`，PATCH省略保留原值。系统页可编辑、保存、刷新恢复，0停止新付费调用；与金额预算同时生效。Worker在后续请求前读取有效配置，重试计次，UTC日重置。管理页显示今日已预留调用与上限，旧后端未提供字段时禁用此项并解释升级需求，避免伪报保存成功。

## X 官方采集与凭据

- 管理页独立 X 面板：启停、Bearer Token写入/清除、关注账号、可选关键词、轮询间隔、单页数量、每日请求上限、连接测试、用量与最近状态、来源入口、接入步骤和官方链接。仅保存 Token 是否已配置；Token 加密存 PostgreSQL，不回显、不进浏览器持久存储、日志或URL。
- `XConfig` 字段：enabled=false；usernames=[]（最多20个、每个1..15字符）；keywords=[]（最多10项，每项1..40字符，作为字面搜索词，不接受操作符）；pollIntervalSeconds=900（300..86400）；maxResults=10（10..100）；dailyRequestLimit=24（0..500）；candidateMinAuthors=3（2..20）；candidateWindowMinutes=60（15..60）。官方只读端点固定 `https://api.x.com/2/tweets/search/recent`，不支持任意出站地址。
- 按账号OR + 可选关键词OR构建最长512字符查询，排除转发/回复；不扩展用户资料，保留真实 author_id 与原帖链接，避免额外资料读取。作者受欢迎、蓝V或被关注不构成项目官方验证。单帖保存为 UNVERIFIED / P3 / SOCIAL_POST，不逐条AI分析。
- 首次仅回看15分钟；每次最多一页，保存分页基线和next_token，页序完成后才推进 newest_id；中断后按持久游标恢复，不默默跳过未采集页。查询范围改变另建游标scope；不把采样窗口称为全网热点。
- DB事务预留每日X请求数（测试和失败请求也计数，UTC日），达到上限停止请求并显示；默认24次×每页10条是返回资源上界估算，不是供应商账单。429遵守reset/Retry-After；401/402/403明确提示凭据/credits/权限，不自动重试付费请求。超时20秒、响应大小上限、固定HTTPS与现有安全传输。密钥或范围配置变化由Worker热同步，无需重建镜像。
- Fixture允许保存配置，但连接测试显示 skipped、采集不向X发请求；live无Token/账号/未启用时显示真实未配置/已停用，不回退样本。调试测试只读一个最小页、不入业务流、不调用AI，且可能产生X读取费用；展示最多3条真实返回摘要和明确时间，失败不展示原始供应商错误正文。

## 多账号讨论候选

在持久原帖中免费聚合明确的 hashtag/cashtag 与管理员关键词；不同author_id、原创正文去重，保存证据，不把账号数称为独立组织确认，不把同名ticker当成真实链上资产。窗口为最近配置分钟，以真实帖子发布时间和系统可得时间截断；帖子逐条分析保持关闭。

同一主题达到 candidateMinAuthors 且至少相同数量原创正文时，建立 `X_HOT_TOPIC` 研究候选，保留 UNVERIFIED、P2、未知参与条件与独立风险提示。只表示所关注账号中的讨论汇聚，不声称全网趋势/买入机会或已确认热度增长。同主题6小时冷却，仍受全局AI日额度/候选容量与一小时有效期保护；没有AI额度则保留候选与跳过原因。

X候选规则提醒只允许P2/P3，并在有效AI解读完成后按用户规则决定外发；AI结论不修改来源验证或独立风险。原始单帖不触发通用通知。连接测试/查看调试结果不会生成研究通知。没有规则/渠道时只在平台保存研究结果。不得把缺少真实Token的合成验证声称为X已联通。

## 接入步骤（管理页同步展示）

1. 打开 [X Developer Console](https://console.x.com)，登录并完成开发者资料与协议。
2. 创建 App，在凭据页获取用于读取公开数据的 Bearer Token。
3. 在 X 控制台确认 recent search 的访问权限、credits与消费上限；X数据费用和AI费用分开。
4. 在本平台系统管理的X面板填写Token、关注账号、采集范围和额度，先保存，保持采集关闭。
5. 点击连接测试，查看权限、费用额度、样本时间或失败原因；测试也可能产生读取费用。
6. 测试成功后启用采集，查看最近采集与今日请求数；来源页面检查游标/错误，调整关键词与作者门槛。

官方核验来源（2026-11-05）：[接入](https://docs.x.com/x-api/getting-started/getting-access)、[近期搜索](https://docs.x.com/x-api/posts/search/quickstart/recent-search)、[分页](https://docs.x.com/x-api/posts/search/integrate/paginate)、[限流](https://docs.x.com/x-api/fundamentals/rate-limits)、[费用](https://docs.x.com/x-api/getting-started/pricing)。当前官方描述为预购credits、按返回资源收费；费率和账号权限以实际控制台为准，页面不硬编码固定美元账单。

## AI 每日调用上限管理

- 管理端 AI 配置增加 `maxDailyCalls`，范围为 0–500 的整数，默认 20；0 暂停新的真实请求。上限同时覆盖后台分析、重试和手动连接测试，UTC 日内所有真实预算预留均计一次。分析与连接测试继续共用数据库预算事务锁及金额预算。
- 配置保存至现有 `system_settings`，GET 与系统状态返回生效值，后续任务热读取，无需重启。旧存储缺少字段时沿用服务器 `AI_MAX_DAILY_CALLS`，未修改此字段的 PATCH 不重置已保存值；不新增数据库迁移。
- AI 面板提供数字输入、0 暂停提示及保存后的上限，系统状态同时显示今日调用与上限。前端检测 API 字段支持，旧服务器禁用该输入且 PATCH 不发送未知字段；不将前端默认值伪称为服务器已经启用的限制。
- Fixture 连接测试继续明确跳过外部服务。密钥仍只在服务器加密保存，不因本配置进入浏览器存储。
