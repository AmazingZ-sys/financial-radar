# 02 可行性研究与范围决策

设计基线：2026-11-02；在业务实现之前编写。完整数据源证据见 [03-data-sources.md](03-data-sources.md)。

## 技术可行性

指定 Vue 3 / Hono / Node LTS / PostgreSQL / Redis / BullMQ 能覆盖模块化单体与分离 API、Worker。首版采用单管理员，持久事实保存在 PostgreSQL，Redis 仅处理协调、缓存、队列与短期限制。GitHub Releases / Fed RSS / Coinbase 公共行情可用已公开契约实现初期真实来源。无数据授权时软件仍可使用清晰标记的 Fixture 验证全流程。

跨来源事件不能只靠标题相似度。链上资产主键至少包含 chain + network + contract/mint/inscription/rune ID；同 ticker 不代表同项目。所有公开时间、观察时间分开持久化；规则优先，AI 在异步队列补充解释。机会与风险是两个独立维度，不能以高机会覆盖高风险。

## 实际发现的冲突与兼容方案

1. **FRED 授权**：当前官方 legal API 附加条款包含 AI 相关使用及存储/缓存限制，与全量原始入库、AI分析不兼容。默认不启用 FRED live；只保留 provider 扩展与 Fixture，后续获得具体书面授权再接入。宏观优先 Treasury/BLS/EIA 原始官方数据。
2. **Coinbase 分发**：官方市场数据条款限制个人/实体内部研究。单管理员私有研究部署可按许可范围评估；公开多用户平台必须取得许可，不以免费端点为依据宣称自由分发。
3. **早期全链监控**：DEX profile/boost、交易所上市都不是链上首次出现的完整索引。MVP 明确监控范围与覆盖缺口，Bitcoin 使用已授权 indexer 后扩展，EVM 从指定 factory 日志开始，Solana 从指定 program 开始。
4. **Node LTS 环境**：开发机现有 Node 20 不代表目标生产版本。工具链与 Docker 明确固定受支持 LTS，并在 CI 验证；若本地暂用兼容版本，验收单独记录。
5. **生产外部依赖**：缺 GHCR/Netlify/服务器/Telegram/LLM 密钥，仍交付构建、配置、健康检查、回滚与测试。真正生产外部推送和发布只在相应凭据与环境具备后验收。

## 全链方案比较

| 方案                | 发现范围                         | 延迟与恢复                                        | 成本/限制                   | 首版选择                       |
| ------------------- | -------------------------------- | ------------------------------------------------- | --------------------------- | ------------------------------ |
| 公共 RPC            | 指定 RPC 请求/订阅，非完整持久流 | 无 SLA，断线可能丢失，需 HTTP 补拉                | 免费但受限，不适合全链生产  | 仅开发，不作为全链保证         |
| 授权索引器          | provider 支持协议/链范围         | 可利用 checkpoint/history，但覆盖与保留需合同确认 | 按套餐/请求/数据量收费      | Bitcoin/EVM/Solana优先扩展方向 |
| 私有 RPC+自建轻索引 | 指定合约/program，控制解析       | 保存 finalized cursor、重组撤回与补偿             | 节点费+数据库/运维          | 阶段性支持 factory/program     |
| 自建全节点+完整索引 | 自主范围，但协议仍需解析实现     | 同步、重索引、硬件故障决定时效                    | 大存储、带宽、开发与24h运维 | 后续预算与容量测试通过再做     |
| 合法官方公告/RSS    | 官方公开阶段，无法捕捉未公告部署 | 可审计，轮询窗口可度量                            | 低成本、范围有限            | 首版真实采集主路径             |

## 首版交付与验收边界

交付可部署纵向链路：来源采集/Fixture→原始留存→标准事件→确定性去重→规则/机会/风险→通知 outbox→Telegram provider→状态/尝试记录→Web 可追溯展示。规则 CRUD、渠道测试、观察列表、回放、AI降级、系统健康与基础成本统计包含在设计范围。黄金/原油实时授权、所有链全量、社交全网以及真实 ORDI 回测不因 Fixture 通过而标记为实现。

验收分四类：代码已实现、自动化已验证、当前环境已运行、需要外部授权/基础设施验证。文档完成不代表系统生产可用，必须按阶段留下命令与结果。
