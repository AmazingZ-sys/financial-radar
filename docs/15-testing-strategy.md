# 15 · 测试与阶段验收策略

设计日期：2026-11-02。目标是验证信号可信度、幂等性、故障恢复与真实可部署性；测试只证明已执行的范围。

## 1. 分层测试

| 层             | 工具与环境                           | 必须验证                                                                    |
| -------------- | ------------------------------------ | --------------------------------------------------------------------------- |
| 契约与算法单测 | Vitest，固定时钟/Fixture             | URL 规范化、跨合约不合并、权重版本、风险独立、生命周期、规则比较、时间窗    |
| Connector 单测 | 受控 HTTP fake                       | 正常/空响应、超时、429 Retry-After、5xx 退避、坏 Schema、checkpoint、不泄密 |
| AI 单测        | Provider stub                        | JSON 校验、证据 ID 约束、未知事实、预算并发控制、缓存、失败降级             |
| 通知单测       | Provider stub                        | 模板转义、渠道开关、优先级、时段、冷却、重复保护、接受与已读区别            |
| API 集成       | Hono request + 真实 PostgreSQL/Redis | 登录/CSRF/权限、Schema、分页过滤、规则 CRUD/test、健康状态、审计            |
| Pipeline 集成  | 真实 PostgreSQL/Redis/BullMQ         | raw 保存→事件→信号→outbox→通知，重复输入幂等，事务失败无半成品              |
| 前端组件/构建  | Vitest/vue-tsc/Vite                  | 格式器、响应校验、空值与错误状态、严格类型、依赖边界                        |
| 浏览器 E2E     | Playwright                           | 登录、过滤、详情、规则变更、通知测试、主题、移动端、API 故障重试            |
| 部署           | shell 检查 + Docker Compose          | 迁移重复运行、健康检查、持久卷、部署失败回滚、备份恢复                      |

单元测试禁止访问真实第三方 API 或真实消息渠道。在线 Connector smoke 需显式启用，只进行只读请求，记录日期/状态，不要求外部免费服务永不失败。Telegram 真正发送属于具备凭据和授权后的联通测试，默认 test double 不宣称已发送。

## 2. 信号与历史回放

Fixture 明确标识 synthetic，不声称重建 ORDI 历史收益。使用同一批历史输入分别按时间顺序和重复顺序执行：结果稳定、不会使用 asOf 后发布/可观察到的信息、不同合约不错误聚合。

测试项目风险很高且机会分很高时，前端与通知仍保留严重风险警告；没有官方核验时不自动提升 VERIFIED；sourcePublishedAt 未知时不计算虚假的负延迟。评分解释包含使用的指标、缺失字段、权重和算法版本。

## 3. 故障注入矩阵

| 故障                  | 预期行为                                          | 验证方式             |
| --------------------- | ------------------------------------------------- | -------------------- |
| 外部 API 超时/限流    | 有界重试，记录失败，熔断后探测恢复                | stub + fake timer    |
| PostgreSQL 重启       | 事务重试/任务失败重投，无 raw/event 丢失          | 集成环境暂停服务     |
| Redis 重启            | API readiness 降级，Worker 重连，PG outbox 可补投 | 集成环境暂停服务     |
| Worker 中途退出       | stalled job 恢复；唯一约束防重复                  | 流程中终止进程再启动 |
| AI 不可用/超预算      | 采集规则不停，P0/P1 仍决策，分析留失败/待重试     | provider fake        |
| Telegram 429/5xx      | 通知 RETRYING，有 attempt 与退避                  | HTTP stub            |
| 请求成功后连接中断    | 标识不确定，避免假称已读；幂等边界有记录          | provider fake        |
| 相同输入重复 10 次    | 一条来源事实、一组合法信号、一次冷却窗口通知      | pipeline 集成        |
| 迁移失败/新版本不健康 | 部署中止或回旧应用，不自动还原 DB                 | 部署测试环境         |

## 4. 安全与质量门禁

CI 执行 frozen lockfile、TypeScript strict、ESLint、Prettier、Vitest、数据库迁移与关键集成、构建、E2E、secret 扫描和生产依赖审计。严重问题失败，临时豁免必须有原因与截止时间。不得为了绿色 CI 忽略所有安全问题或跳过全部集成测试。

必要断言包括：未认证 401，错误 CSRF/Origin 403，非法规则 400，登录限流，普通管理接口无完整凭据，输出无脚本执行，重复通知不会因 API 重试无限发送，随机项目 ID 不越权。

## 5. 性能、时效与验收记录

性能基线在固定测试环境记录硬件/样本数：事件列表索引命中、100 条分页上限、Worker 并发受配置约束，历史查询有起止时间和数量上限。P50/P95 对实际样本计算，并展示样本数、窗口与无效时间字段数量，不用固定常量冒充指标。

每阶段在 `docs/implementation-log.md` 记录开始/结束、交付文件、执行命令、结果、限制和下一步。只有真实通过的测试写“通过”；Docker daemon/外部 key/生产权限不可用写“未执行：原因”。文档完成是阶段门禁，不是整个项目完成。
